## What the engine now does

- The Go runtime journals each automatic wave's origin, local zone, composition, destination, revision, and durable request IDs before dispatch. Every native spawn receives that destination; OpenBW issues attack-move and retains combat authority. An ordinary park revision no longer resets the rally order. An idle actor can retry once, or retry after a blocked unit-width route becomes open again.
- Native precommit checks use actual OpenBW pathfinding for a hypothetical unit of each wave type, in addition to endpoint footprint, occupancy, elevation, and region checks. The bridge's tile-mask search remains a coarse candidate filter. Native query work is bounded to at most 64 sampled candidates per due wave.
- The browser plugin queues settings behind staged park revisions and stamps the confirmed revision when sending. Only the commander can change the shared setting. Rejected edits leave the authoritative status in place.

## Cache migration and bounded work

The v2 automatic-perimeter preset changes the prepared-package key. For Fungus Woods, the old v1 key `a183db…` was retained and the new v2 key `e6957c…` required one validated preflight. The first v2 build took 23.104 s including 19.040 s preflight; native map generation itself took 55.574 ms. A second build reused the package in 2.212 s; fresh materializations took 1.105 and 1.001 s. The v1 and v2 native map SHA-256 were identical (`02cf274d…`). Evidence: `run-data/map-cache/timings.jsonl`, `run-data/cache-v2-reuse-1/cache-materialization.json`, and `run-data/cache-v2-reuse-2/cache-materialization.json`. Thus the preset requires one preflight cache rebuild, but did not regenerate expensive map geometry.

Selection runs only when a wave is due, on confirmed relevant geometry changes before submission, or at a 240-frame no-route retry. The 256 × 256 measured 15.6–22.9 ms for candidate enumeration and 0.19–0.21 ms for a native route query on this Pi. No per-tick full-map candidate scan was observed.
