# Passthrough RTS Bridge

This project is a proof of concept for showing one genuine OpenBW-simulated Zergling inside a shared OpenRCT2 park. A headless OpenBW/BWAPI module owns the unit's movement; an OpenRCT2 multiplayer server distributes its state to two modified graphical clients, which render an independently illustrated stand-in creature in the park scene.

Start with the [Rev 2 implementation specification](docs/specification.md), [repository layout](docs/repository-layout.md), and [bootstrap guide](docs/bootstrap.md). The [bridge protocol](bridge-protocol/README.md) has the first schema and fixture. The earlier Recoil/Minecraft proposal and Raspberry Pi assessment are kept in the [documentation archive](docs/archive/README.md) for historical reference.

The working tree keeps pinned upstream checkouts under ignored `upstream/`; `scripts/fetch-upstream.py` restores them after cloning this Git repository. The tracked source includes build scripts, a BWAPI module, an OpenRCT2 native render patch, and a server-distributed plugin. On this Pi, the live bridge ran for 65 seconds with one headless BWAPI launcher, one OpenRCT2 host, and two graphical clients. All 514 snapshots seen by all three OpenRCT2 participants matched in application tick, unit identity, and coordinates; both clients rendered the moving stand-in creature. See the [test record](docs/headless-test-2026-10-10.md) and [run instructions](docs/bootstrap.md).

To repeat the graphical capture here after building, run `python3 scripts/capture-live-demo.py --seconds 65`. It uses the user-supplied game data at `/home/pi/games/starcraft` and `/home/pi/games/rct2`, starts two virtual displays, and saves screenshots and logs under ignored `run-data/visual-demo/`. The game assets and captured RCT2 graphics are kept out of Git.
